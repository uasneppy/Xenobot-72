Pre-built binaries are available for all major platforms, making it easy to deploy Xenobot-72 without Docker or building from source.

## Available Platforms

| Platform | Architecture | Archive Name |
|----------|-------------|-------------|
| Linux | amd64 | `xenobot-72_linux_amd64.tar.gz` |
| Linux | arm64 | `xenobot-72_linux_arm64.tar.gz` |
| macOS | amd64 (Intel) | `xenobot-72_macOS_amd64.tar.gz` |
| macOS | arm64 (Apple Silicon) | `xenobot-72_macOS_arm64.tar.gz` |
| Windows | amd64 | `xenobot-72_windows_amd64.zip` |
| Windows | arm64 | `xenobot-72_windows_arm64.zip` |

:::note[Binary Name]
The binary inside every archive is named `xenobot-72` (or `xenobot-72.exe` on Windows). This is consistent across all platforms.
:::

:::caution[Platform Selection]
Make sure you download the correct binary for your platform and architecture. Running the wrong binary will result in an "exec format error" or similar failure.
:::

## Download

Download the latest release from GitHub:

```bash
# Get the latest release version
VERSION=$(curl -s https://api.github.com/repos/uasneppy/Xenobot-72/releases/latest | grep tag_name | cut -d '"' -f 4)

# Download for Linux amd64
curl -LO "https://github.com/uasneppy/Xenobot-72/releases/download/${VERSION}/xenobot-72_${VERSION}_linux_amd64.tar.gz"

# Extract
tar -xzf xenobot-72_${VERSION}_linux_amd64.tar.gz

# Make executable
chmod +x xenobot-72
```

Or visit the [GitHub Releases](https://github.com/uasneppy/Xenobot-72/releases) page to download manually.

## Verify Checksums

Each release includes a `checksums.txt` file with SHA256 hashes:

```bash
# Download checksums
curl -LO "https://github.com/uasneppy/Xenobot-72/releases/download/${VERSION}/checksums.txt"

# Verify
sha256sum -c checksums.txt --ignore-missing
```

:::tip
Always verify checksums after downloading to ensure the binary has not been tampered with or corrupted during transfer.
:::

## Systemd Service (Linux)

For production deployments on Linux, run Xenobot-72 as a systemd service.

### Create Service File

```bash
sudo nano /etc/systemd/system/xenobot-72.service
```

Add the following content:

```ini
[Unit]
Description=Xenobot-72 Telegram Bot
After=network.target postgresql.service redis.service
Wants=postgresql.service redis.service

[Service]
Type=simple
User=xenobot
Group=xenobot
WorkingDirectory=/opt/xenobot-72
ExecStart=/opt/xenobot-72/xenobot-72
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

# Environment file
EnvironmentFile=/opt/xenobot-72/.env

# Resource limits
LimitNOFILE=65535
MemoryMax=1G
CPUQuota=100%

# Security hardening
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
PrivateDevices=true
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictSUIDSGID=true
RestrictNamespaces=true

[Install]
WantedBy=multi-user.target
```

### Setup

<Steps>
  <Step title="Create user and directory">
    ```bash
    sudo useradd -r -s /bin/false xenobot
    sudo mkdir -p /opt/xenobot-72
    sudo chown xenobot:xenobot /opt/xenobot-72
    ```
  </Step>

  <Step title="Copy binary and config">
    ```bash
    sudo cp xenobot-72 /opt/xenobot-72/
    sudo cp .env /opt/xenobot-72/
    sudo chmod 600 /opt/xenobot-72/.env
    sudo chown xenobot:xenobot /opt/xenobot-72/*
    ```
  </Step>

  <Step title="Copy migrations if using auto-migrate">
    ```bash
    sudo cp -r migrations /opt/xenobot-72/
    ```
  </Step>

  <Step title="Reload systemd and enable service">
    ```bash
    sudo systemctl daemon-reload
    sudo systemctl enable xenobot-72
    ```
  </Step>
</Steps>

### Service Management

```bash
# Start the service
sudo systemctl start xenobot-72

# Check status
sudo systemctl status xenobot-72

# View logs
sudo journalctl -u xenobot-72 -f

# Stop the service
sudo systemctl stop xenobot-72

# Restart the service
sudo systemctl restart xenobot-72
```

## Log Rotation

Configure log rotation for journald logs:

```bash
sudo nano /etc/systemd/journald.conf.d/xenobot-72.conf
```

```ini
[Journal]
SystemMaxUse=500M
SystemMaxFileSize=50M
MaxRetentionSec=1month
```

Or use a dedicated log file with logrotate:

```bash
sudo nano /etc/logrotate.d/xenobot-72
```

```
/var/log/xenobot-72/*.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    create 640 xenobot xenobot
    postrotate
        systemctl reload xenobot-72 > /dev/null 2>&1 || true
    endscript
}
```

## Environment File

Create `/opt/xenobot-72/.env`:

```bash
# Required
BOT_TOKEN=your_bot_token
OWNER_ID=your_telegram_id
MESSAGE_DUMP=-100xxxxxxxxxx
DATABASE_URL=postgresql://xenobot:change-me@localhost:5432/xenobot

# Redis endpoint (optional when Redis is at localhost:6379)
# REDIS_ADDRESS=redis-host:6379
# REDIS_URL=redis://user:password@redis-host:6379/1

# Optional
AUTO_MIGRATE=true
HTTP_PORT=8080
DEBUG=false

# Webhook mode (optional)
# USE_WEBHOOKS=true
# WEBHOOK_DOMAIN=https://your-domain.com
# WEBHOOK_SECRET=your-secret

# Performance tuning
DB_MAX_OPEN_CONNS=200
DISPATCHER_MAX_ROUTINES=200
```

:::caution[File Permissions]
Always set restrictive permissions on the `.env` file since it contains sensitive credentials like `BOT_TOKEN` and database passwords. Use `chmod 600` so only the service user can read it.
:::

### Create a Launch Agent (Optional)

For automatic startup on macOS:

```bash
mkdir -p ~/Library/LaunchAgents
nano ~/Library/LaunchAgents/com.xenobot-72.plist
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.xenobot-72</string>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/local/bin/xenobot-72</string>
    </array>
    <key>WorkingDirectory</key>
    <string>/usr/local/etc/xenobot-72</string>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
    <key>StandardOutPath</key>
    <string>/usr/local/var/log/xenobot-72.log</string>
    <key>StandardErrorPath</key>
    <string>/usr/local/var/log/xenobot-72.log</string>
</dict>
</plist>
```

Load the agent:

```bash
launchctl load ~/Library/LaunchAgents/com.xenobot-72.plist
```

## Windows Installation

### Download and Extract

1. Download the Windows binary from [GitHub Releases](https://github.com/uasneppy/Xenobot-72/releases)
2. Extract the ZIP file to a directory (e.g., `C:\xenobot-72`)
3. Create a `.env` file in the same directory

### Run as a Service

Use [NSSM](https://nssm.cc/) (Non-Sucking Service Manager) to run as a Windows service:

```powershell
# Install NSSM
choco install nssm

# Install service
nssm install Xenobot72 C:\xenobot-72\xenobot-72.exe
nssm set Xenobot72 AppDirectory C:\xenobot-72
nssm set Xenobot72 AppEnvironmentExtra BOT_TOKEN=your_token
nssm set Xenobot72 Start SERVICE_AUTO_START

# Start service
nssm start Xenobot72
```

## Troubleshooting

### Permission denied

```bash
chmod +x xenobot-72
```

### Library not found

:::tip
The binary is statically compiled, so no external libraries are needed. If you see library errors, ensure you downloaded the correct platform binary.
:::

### Cannot connect to database

Verify PostgreSQL is running and accessible:

```bash
psql -h localhost -U postgres -d xenobot -c "SELECT 1"
```

### Service won't start

Check the logs:

```bash
sudo journalctl -u xenobot-72 -n 50
```

Common issues:
- Invalid environment variables
- Database connection failed
- Redis not running
