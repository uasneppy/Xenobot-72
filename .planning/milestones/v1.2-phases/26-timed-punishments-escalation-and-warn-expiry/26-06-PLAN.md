## Phase Goal

**As a** group owner, **I want** to make my group's automatic punishments timed, escalate repeat offenders step by step and let old warns
expire, **so that** a first slip costs less than a pattern of abuse, while a group that sets none of this keeps every reply and punishment
exactly as it is today.

This plan gives each warn a time and one counting rule that every reader and writer shares. The page that turns expiry on comes in plan 26-07.

<objective>
Add the per-warn time and the group's expiry setting, make every warn reader and writer count the same warns through one rule in the model,
and carry the phase's new values through the backup export and import.

Purpose: TUNE-03 ("a warn older than N days no longer counts toward the limit, and /warns shows what counts"), and the backup half of D-37 for
TUNE-01's durations.
Output: one migration, the counting rule, the repository's dated functions, the commands' counted replies, the backup changes, and their tests.

Test time budget (D-45): about 3 s of the phase's 35 s in `fuku/modules`, plus `fuku/db` tests in `test-rest`.
</objective>

// WarnSettings gains ExpiryDays int (column warn_expiry_days, json "warn_expiry_days,omitempty"); 0 is off.
// Warns gains WarnTimes Int64Array (column warn_times, json "warn_times,omitempty"): the unix seconds of each stored warn.
const WarnExpiryMaxDays = 365
// NormalisedTimes returns exactly NumWarns non-decreasing times: missing ones are padded at the front with
// min(UpdatedAt, the first stored time), extra ones are cut from the end. A zero UpdatedAt (a value cached by the previous
// build) pads with the far future, so such a warn never expires on a guess.
func (w *Warns) NormalisedTimes() []int64
// Counted returns how many warns count, their reasons (the last min(count, len(Reasons)) reasons) and their times: every warn
// with expiry off, else the warns whose time is after now - expiryDays*24h (a suffix, the times being non-decreasing).
func (w *Warns) Counted(expiryDays int, now time.Time) (count int, reasons []string, times []int64)

## Planner assumptions (flagged)

- The counting rule is based on `num_warns`, not on the length of the reasons, because a row can hold fewer reasons than warns (an import, the
  plan 26-01 case `warns_no_reasons`). With expiry off, `Counted` returns `num_warns` and every reason, so every display stays byte for byte.
- With expiry off, `RemoveWarnAt` and `ResetUserWarnsAt` keep today's exact answers: `RemoveWarn` decrements while `num_warns > 0`, and
  `ResetUserWarns` answers removed when a row was deleted, even a row with no warn left. With expiry on, they answer by the counted warns
  (D-35). Only expiry on changes an answer.
- `/warns` keeps reading the limit through `GetWarnSettingContext`, as today (that read already creates the row for a known chat), and takes
  the expiry from the same row. `GetWarnsAt` reads the expiry through `LoadWarnSettingsContext`, which creates nothing, so the AI spam path
  creates no row.
- The plan 26-01 export golden seeds a row with no times and no expiry, so its export stays byte for byte: times are exported only as stored
  and only when there is one per warn.
- `fuku/db/backup` imports `fuku/db/models` for `PunishDurationValid` and `WarnExpiryMaxDays` (plan 26-02), never `fuku/modules`.
