## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings / Command Callers → `xenobot/db/presence` → PostgreSQL | Archive target IDs, thresholds, and delivery modes enter persistent storage and `skipLocal` cache. |
| Concurrent Reaction Updates → `chat_presence_archived` | Multiple replicas attempt to claim the same viral message simultaneously. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-04 | Tampering | `SetArchiveThreshold` / `SetArchiveEmojiMode` / `SetArchiveDelivery` | medium | mitigate | Validate `ValidArchiveThreshold` (`2..50`), `ValidArchiveEmojiMode` (`positive`/`all`), and `ValidArchiveDelivery` (`copy`/`forward`) before DB writes, backed by inline SQL `CHECK` constraints. |
| T-33-05 | Repudiation / Integrity | `TryClaimArchived` (`chat_presence_archived`) | high | mitigate | Enforce composite primary key `pk_chat_presence_archived (chat_id, message_id)` with `ON CONFLICT DO NOTHING` returning `RowsAffected == 1` so only one replica ever claims a message. |
| T-33-06 | Integrity | Rolling-deploy cache (`chat_presence:<chat>`) & `ReplacePortableTx` | high | mitigate | Normalize zero/empty Phase 33 fields in `Get()`/`GetFresh()` and never accept `archive_chat_id`/`archive_thread_id` in `ReplacePortableTx` (preserving target chat's verified target). |
| T-33-SC | Tampering | Go module dependencies | high | accept | Zero new external Go packages added. |
</threat_model>
