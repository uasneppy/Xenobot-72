    Update `xenobot/modules/chat_log.go` (for `CHAT-01`):
    1. Add `At int64` with tag `json:"at,omitempty"` to `chatLogEntry`.
    2. In `chatLogEntryOf(msg *gotgbot.Message, userID int64)`, populate `At: msg.Date` (NEVER `time.Now().Unix()`).
    3. In `chatLogEdit(client *redis.Client, chatID int64, entry chatLogEntry) (bool, error)`:
       - Before setting `entry.Edited = true` and calling `chatLogWrite(client, chatLogEditScript, chatID, entry)`, read the existing entry at score `entry.MessageID` via `chatLogEntryAt(context.Background(), client, chatID, entry.MessageID)`.
       - If an existing entry exists with `existing.At > 0`, set `entry.At = existing.At` so message edits never overwrite or drop the original creation timestamp even if a caller passes a different or zero `At`.
    4. Implement four thread-isolated query helpers in `chat_log.go` (all bounding Redis reads with `rCtx, cancel := context.WithTimeout(ctx, chatLogReadTimeout)`):
       - `chatLogEntryAt(ctx context.Context, client *redis.Client, chatID, messageID int64) (chatLogEntry, bool, error)`: reads score `[messageID, messageID]` via `ZRangeArgs{Key: chatLogKey(chatID), Start: id, Stop: id, ByScore: true}` and unmarshals `chatLogEntry`. Returns `(zero, false, nil)` when absent or malformed.
       - `chatLogRecent(ctx context.Context, client *redis.Client, chatID, threadID, beforeMsgID int64, limit int) ([]chatLogEntry, error)`: reverse scan over the ring (`ZRevRange(rCtx, chatLogKey(chatID), 0, -1)`), skipping entries where `entry.Thread != threadID || (beforeMsgID > 0 && entry.MessageID >= beforeMsgID)`, collecting up to `limit` matches, then `slices.Reverse(entries)` so result is oldest-first.
       - `chatLogSinceUser(ctx context.Context, client *redis.Client, chatID, threadID, userID, beforeMsgID int64) ([]chatLogEntry, error)`: reverse scan over the ring (`ZRevRange` `0 .. -1`), keeping only `entry.Thread == threadID && (beforeMsgID <= 0 || entry.MessageID < beforeMsgID)` entries until the newest matching entry with `entry.UserID == userID` is found (inclusive); if no entry from `userID` exists in that thread, return `(nil, nil)`. Reverse collected entries so result starts at that user's anchor message and runs oldest-first.
       - `chatLogSinceTime(ctx context.Context, client *redis.Client, chatID, threadID, cutoffUnix, beforeMsgID int64) ([]chatLogEntry, error)`: reverse scan over the ring (`ZRevRange` `0 .. -1`), filtering `entry.Thread == threadID && (beforeMsgID <= 0 || entry.MessageID < beforeMsgID)`, skipping legacy entries with `entry.At <= 0` (never falsely pulled into a recent time window), and excluding entries with `entry.At < cutoffUnix` (breaking early once `entry.At > 0 && entry.At < cutoffUnix` only if timestamps are strictly monotonic — better yet, continue scanning or break only after checking monotonic invariants; since ring size `chatLogMax` is at most 1000, scanning the filtered entries cleanly handles out-of-order `At` or mixed `At == 0` legacy entries safely). Reverse collected entries to oldest-first.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram `EditedMessage` → `chatLogEdit` → Redis ZSET | Edited messages carry `EditDate` and could overwrite original creation timestamps if trusted blindly. |
| Multi-Topic Supergroup Redis Ring → Brief / Ambient Queries | Entries from different forum topics share one per-chat ZSET (`xenobot:chat:{<chat>}:log`) and must never bleed across topics. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-06 | Tampering / Integrity | `chatLogEdit` & `chatLogSinceTime` | low | mitigate | Read existing ZSET score entry inside `chatLogEdit` and preserve `existing.At > 0`; ignore `At <= 0` legacy entries in `chatLogSinceTime`. |
| T-34-07 | Information Disclosure | `chatLogRecent`, `chatLogSinceUser`, `chatLogSinceTime`, `chatLogRecentThread` | medium | mitigate | Enforce `entry.Thread == threadID` on every single entry in every query helper so private/topic conversations never cross topic boundaries. |
| T-34-SC | Tampering | Go module dependencies | high | accept | Zero new external Go packages added. |
