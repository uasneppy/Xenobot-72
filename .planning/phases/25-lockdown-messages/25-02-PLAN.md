## Phase Goal

**As a** group owner, **I want** to set what the bot posts in my group when a lockdown starts and when it is lifted, **so that** these messages sound like
my community, while the technical notes, the alerts and every raid-scale path stay exactly as they are and a group that sets nothing sees no change.

<objective>
Prove the lockdown path end to end on the manual start: `/lockdown` posts a stored custom message through the engine, from a non-lockdown adapter file,
with the technical notes appended, never queued for deletion; then add the four other event keys, the `{percent}` placeholder, the engine's lockdown input
fields and the default builders of the automatic notices and the lift, each proven byte for byte against the goldens of plan 25-01 before their sites
switch; and install the structural EVT-10 guard over every caller of the engine, so every later plan of the phase runs under it.

Purpose: the riskiest structural change (a lockdown file reaching the engine) is made and guarded first, on the simplest site.
Output: the keys, the vocabulary, the adapter file with the manual start site and all five builders, their tests, the guard and the AGENTS.md lines.

Test time budget (D-39): about 3 s of the phase's 28 s. One lockdown environment per subtest; the language sweep of Task 2 is over pure renders only; the
guard is a parse of the package's files.
</objective>
