## Provisional Owner Decisions Recorded Here (Easy to Confirm or Reverse)

- **P28-01 (Safe bounds & default normalization):** Storing `0` in any column means unset/default. Safe bounds: `raid_join_window_secs` `15..600` (default `60`), `raid_flood_window_secs` `10..300` (default `30`), `raid_ai_window_secs` `30..900` (default `120`), `raid_flood_new_percent` `20..100` (default `60`), `raid_flood_min_accounts` `2..20` (default `3`), `raid_recent_hours` `1..168` (default `24`), `raid_ai_image_bar_pct` `50..99` (default `85`), `member_req_ai_bar_pct` `50..99` (default `90`), `member_req_cap_per_min` `3..100` (default `10`), `member_req_pause_mins` `1..60` (default `10`), `lockdown_reminder_mins` `15..1440` (default `60`), `captcha_timeout_mins` `0` or `11..60` (default `0`, deferring to `captcha_settings.timeout`). In `applyAdvancedThreshold`, submitting a value equal to an item's default normalizes storage to `0` so the item cleanly returns to Default state.
- **P28-04 (Fail-to-default on transient read error):** When `advThresholdsLookup` fails on a hot path, it logs one IDs-only debug/warn line and returns zero `advthresholds.Thresholds{}` (compiled defaults) so a transient DB fault never disables raid detection, screening, reminders, or captcha.
