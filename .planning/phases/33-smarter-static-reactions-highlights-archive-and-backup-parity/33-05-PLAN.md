<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Channel / Group `/setarchive` Forward → `presence_archive.go` | Untrusted forwards or topic commands attempt to bind a target archive destination for a group. |
| `MessageReactionUpdated` → Redis SET → `chat_presence_archived` → Telegram API | Untrusted member reactions accumulate toward auto-archiving and trigger `CopyMessage`/`ForwardMessage` into a target channel. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-12 | Elevation of Privilege / Information Disclosure | `setArchive`, `bindSetArchiveForward`, `unsetArchive` | high | mitigate | Verify live admin (`RequireUserAdmin`/`CanUserChangeInfo`) BEFORE `consumePendingMarker` so members cannot burn tokens; reject Staff Groups as BOTH source and destination (`presenceIsStaffGroup`) on link AND before delivery. |
| T-33-13 | Integrity / Abuse | `presenceHandleArchive` reactor counting | medium | mitigate | Track distinct user IDs via `SADD`/`SREM` on `NewReaction` qualifying list (blocking Premium multi-emoji inflation and toggle farming), exclude message author (`presenceLogAuthorOf` + `bot_react`), bots, anonymous actors, and `presenceConsensusHostile`. |
| T-33-14 | Integrity | Viral message re-archiving across Redis flush / replicas | high | mitigate | Claim `(chat_id, message_id)` atomically via PostgreSQL `TryClaimArchived` (`pk_chat_presence_archived`) after lazy `presenceIsLockedDown` check and fast Redis latch. |
| T-33-15 | Tampering / Broken Link | `presenceArchiveJumpURL` on legacy `group` chats | low | mitigate | Guard `t.me/c/` link construction strictly to `supergroup` (`-100...`) or public `Username`, omitting inline URL markup on legacy `"group"` chats. |
| T-33-SC | Tampering | Go module dependencies | high | accept | Zero new external Go packages added. |
</threat_model>
