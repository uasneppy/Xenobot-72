## Phase Goal

**As a** group owner, **I want** to customize the message for a failed captcha and the notices for member requirement breaches, and to turn on a
rate-limited notice for AI spam deletions, **so that** these messages sound like my community, while a group that sets nothing sees no change.

This plan is the phase's tracer and its engine extension: the captcha failure message goes end to end first, through the timer and the web check,
then the rest of the engine's vocabulary (event keys, the off-by-default rule, the site hooks, the words) and the default builders are added for the
plans that follow.

<objective>
Prove the screening path end to end on the failed captcha: a site with no update and no moderation context (`handleCaptchaTimeout`, reached by the
timer and by the web check's `Fail`) posts a custom message through the engine, keeps today's 30 second self-delete through a new `Schedule` hook and
never enters the deletion queue; then add the five other event keys, the off-by-default rule of the AI spam event, the engine hooks the requirement and
AI sites need (`SendCustom`, `Admit`, `Required`, `TextOnly`, `Rules`, `postEventSent`), the new words, and the default builders of all six events, each
proven byte for byte against the goldens of plan 24-01 before any other site is switched.

Purpose: the riskiest changes (the engine's new hooks under every earlier golden, the captcha site on the web verify route) are made and proven first.
Output: the engine hooks, the captcha site, the six keys, the builders and words, their tests and the AGENTS.md lines.

Test time budget (D-40): about 3 s of the phase's 30 s. One site per subtest; the language sweep of Task 3 is over pure renders only.
</objective>

## Planner assumptions (flagged)

- The captcha site (D-17, D-18, D-26): `Bot`; `Chat` `&gotgbot.Chat{Id: chatID, Type: "supergroup", Title: chats.GetChatSettings(chatID).ChatName}`
  (the stored title, no Telegram call; P16); `Tr` the group's translator `handleCaptchaTimeout` already builds; an empty `Actor`; `ReplyTo` and
  `ThreadID` 0; `Kind` empty; `Automatic` true; `SendDefault` `helpers.SendMessageWithErrorHandling(bot, chatID, text, opts)` with the builder's options
  (`&gotgbot.SendMessageOpts{ParseMode: formatting.HTML}`, nothing else); `Schedule` `captchaFailureNoticeDelete`, which starts today's
  `time.AfterFunc(captchaFailureNoticeLife, ...)` delete with its panic recovery for a non-nil message. The reply: event `captcha`, the target, the values
  (Action `eventActionWord(tr, action)`, Count the held messages, Until `time.Now().Add(captchaFailureMuteSpan)` for a mute, Reason
  `captchaEventReason(tr)` from Task 2), and the default from `captchaFailureDefaultReply` (the text `buildCaptchaFailureMessage` builds today from the
  action, the member's ID, the first name with today's "User" fallback and the held count).
- `handleCaptchaTimeout` keeps every step before the notice exactly as it is; it reads the member's full user (first name, last name, username) from the
  `getChatMember` answer it already makes, falling back to `{Id: userID, FirstName: "User"}` on an error, and replaces the notice's send and timer with
  `postCaptchaFailureNotice`, logging a send error as today. `buildCaptchaFailureMessage` stays (the builder calls it), so the default is unchanged by
  construction.
- The web check reaches the notice through `captchaWebBackend.Fail` and `Expire` (`settleCaptchaAttempt` and `expireCaptchaAttemptApplied`), which return
  what they returned before: the notice step does not change the claimed and applied values.
- The group step reads `msgs.Resolve(r.Event, eventmsg.DestGroup)`: Silent (and not `r.Required`) posts nothing; no content is the default; otherwise the
  custom message, composed with the row's media dropped when `r.TextOnly`, sent through `site.SendCustom` (nil: `media.SendGreetingMessage`) and handed to
  `site.Schedule` (nil: `scheduleBotMessage(sent, site.Kind)`); the default path calls the same schedule helper. `Admit`, when set, is called once after
  the read and only when the group message or the private copy would be sent; false posts nothing and offers no private copy. The requirement mask
  `eventDefaultInput.Rules` is read only by the requirement builders.
- The AI notice text `aispam_notice_deleted` takes `{name}` (the member's mention, built and escaped by the builder); English draft: `🧠 I removed a message
  from {name}: it looked like spam.` (P12). `eventmsg_mreq_rules` takes `{rules}`; English draft: `Requirements not met: {rules}.`. `eventmsg_action_delete`
  is `deleted`; `eventmsg_reason_captcha` `did not complete the captcha in time`; `eventmsg_reason_aispam` `the message looked like spam`.
- The requirement note (D-14, P5): `"\n" + eventmsg_mreq_rules(rules) + " " + each remedy of memberReqNoticeRemedies(key, broken)`; `composeEventMessage`
  appends it after a custom text with its own `"\n"`, so a blank line precedes the requirements line. `memberReqNoticeDefault(action)` maps `in.Target`,
  `in.Rules`, `in.Count`, `in.Limit` and `in.Action` (for the warn event: empty or `warn` for the plain notice, `kick`, `ban` or `mute` for the limit action
  that took effect) to `memberReqNoticeText` and returns the options `memberReqPostNotice` builds today (HTML, link previews off, `ReplyMarkup` only when
  `in.Rows` is non-empty).
